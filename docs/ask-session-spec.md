# Ask session memory

Proposed for review. This spec covers Ask in the macOS and Windows desktop app, including questions handed off from Dictate. An Ask session is one conversation in memory. It can outlive the popover losing focus and expire without becoming saved chat history.

## User experience

| User action                                                                                 | Expected result                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Invoke Mauz with no eligible chat and choose Ask                                            | Open a fresh conversation. Stage the pointed or selected source for the first question, using the existing capture flow.                                                                                      |
| Scroll the page while Ask keeps focus, then send a follow-up                                | Keep the conversation and the composer. A question about the previous answer uses the transcript. To ask about a new paragraph or visual, point at it and invoke Mauz again.                                  |
| Click the page, scroll, and invoke Mauz again on the same document within the resume window | Open Ask directly with the transcript visible and the input focused. Stage the newly pointed source for review when it differs from the last source.                                                          |
| Invoke Mauz while pointing inside the open Ask panel                                        | Focus the existing composer and keep its draft and staged source.                                                                                                                                             |
| Ask about a different item on the same document                                             | Answer about the new item in the same chat. A clear new subject needs no confirmation.                                                                                                                        |
| Choose **New chat**                                                                         | Start an empty conversation at the current target. Clear the previous dialogue, draft, and historical attachments immediately. Keep a separately staged current target if it is still verified and permitted. |
| Invoke on a different or unverified document, or after expiry                               | Show the usual Mauz menu. Choosing Ask starts fresh. No previous turns or images enter the new request.                                                                                                       |
| Use **Back** from Ask                                                                       | Suspend the chat and show the existing Mauz menu. Ask can reopen the eligible chat. Other menu actions are available from there.                                                                              |
| Explicitly close Mauz or quit                                                               | End the Ask session and clear its data.                                                                                                                                                                       |

Use a provisional **five-minute window from suspension**. The timer runs while the chat is hidden or the user is in another Mauz mode. An open Ask panel stays active while the user reads. Background completion of an answer does not extend the deadline. Starting a fresh Ask replaces the one previous session. Opening a menu without starting Ask allows the previous chat to remain eligible until expiry.

On a matching re-invocation, the short path always opens Ask. Reaching Dictate, Send to agent, or Settings via the dial then takes **Back**. This is the cost of resuming without a chooser. The tray's **Open Mauz** command continues to open the dial. Send to agent keeps its own capture and handoff flow. Dictate → Ask uses the same session selection rules and submits the dictated text once after the session and source are ready.

Reuse the existing popover, Ask accent, formatted answers, and shared button and focus styles. Place the question field directly below the header. Show the scrollable transcript below the composer once there is a turn to display. Show **New chat** and **Back** consistently. On re-point, a removable source label in the composer shows what will accompany the next question, such as `Selected text` or `Screenshot`. When a stream arrives, follow the newest turn while the user is already at the bottom. Preserve their reading position after they scroll up. Announce progress and final results to assistive technology without reading every delta. Enter sends, Shift+Enter inserts a newline, and Enter during IME composition leaves composition in control. Preserve the existing empty first-question shortcut when a source is available. A blank follow-up sends nothing.

## How Mauz matches a page

- **Browser identity** uses the authenticated extension connection, tab ID, and an opaque token generated for the top-level document. Compare the route as well so same-document navigation to a different path or query can start a fresh chat. A jump to an in-page anchor stays in the same chat. Tab IDs, document tokens, and routing keys stay in the desktop process and out of provider prompts.
- **Same page, different target** keeps the session. A changed selection, pointed element, or relevant visual can change the evidence for the next turn independently of page identity.
- **Unverified targets** include a missing or older extension, an ambiguous browser profile, and native apps without a verified document ID. Ask still supports follow-ups while the panel is open. After blur, the next invocation opens a fresh Ask. Window title, bounds, app name, and URL alone are insufficient for automatic resume.
- **Capture restrictions** take precedence over identity and reattachment. A blocked source cannot auto-resume or provide an attachment. Retain the ability to ask a fresh text-only question. If the user changes a capture blocklist during a chat, end that chat and clear its evidence, including earlier answers derived from it.
- **Rapid activations** invalidate older identity and capture results. A late browser reply cannot switch the panel, attach evidence, or revive a session after a newer activation or explicit close.

The browser extension and bridge need a backward-compatible metadata update. Keep the existing browser context fields and make session identity optional during mixed-version installs. An authenticated connection gives the identity its namespace. Reconnection can conservatively require a fresh chat if the binding can no longer be verified. This release does not add background scroll or screenshot monitoring.

## How a turn gets its context

1. **First send.** Use the staged initial source with the existing capture rules. Keep current permission and never-capture checks. The model can still answer an explicit question when capture fails.
2. **Ordinary follow-up.** Send the ordered prior dialogue and the new question. Send no screenshot and no new screen evidence unless the composer shows an attachment. Prior text evidence can remain associated with its historical turn within the prompt budget.
3. **Re-point.** Read the target where the user deliberately invokes Mauz again. Prefer newly selected or pointed text. Stage an image for an identifiable visual such as an image or canvas, or for a target that lacks usable text. When useful text is available, default to it and offer **Include screenshot**. Reuse or hold one eligible crop from the deliberate invocation if needed to preserve the view. The user can remove the staged source before sending. Activation and capture alone never send a model request.
4. **Earlier image.** Keep up to three recent distinct crops per chat, with a total encoded budget of 6 MiB and the existing per-image schema limits. An earlier image still in memory can be selected from its turn via **Attach again**. Comparing two visuals sends the selected earlier crop and the current crop with distinct source labels. If an image has expired or been evicted, show that the user needs to point at it again. When a crop matches previously retained bytes, reuse its local reference. A routine re-point at an unchanged target does not stage duplicate evidence.
5. **Attribution.** The system prompt instructs the model to resolve references from the question, preceding turns, and explicitly attached sources. Mark the latest attachment as current and label older evidence with its originating turn. A reference to an event already discussed should resolve to that event. A question about a newly selected item should use the selection. If the referent remains ambiguous, ask a brief clarifying question. Treat captured content as source material. Never present old evidence as the current view.

When Ask owns focus, the foreground app is Mauz and the pointer may be inside the composer. A refresh must use the target captured on a deliberate re-invocation, or explicitly read the verified source. It must never silently capture the composer or a newly foregrounded app. If the intended target changed or cannot be verified while collecting a crop, discard the crop and offer to capture again. A screenshot failure can fall back to verified text, with a short status when the requested image is unavailable.

## Architecture and request lifecycle

| Layer                                                      | Responsibility                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Electron main and popover lifecycle                        | Own one in-memory Ask session, the activation sequence, capture policy, the expiry timer, and cancellation. Distinguish ordinary blur, internal hide during capture, switching modes, and explicit close. Keep the same session ID across a verified resume.                                                                                                         |
| Browser extension, `BrowserBridge`, and `ContextCollector` | Verify and identify the source, stage permitted evidence on an explicit action, and keep routing metadata separate from the prompt. Pass existing context to other modes through their current paths.                                                                                                                                                                |
| Shared schemas, preload, and IPC handlers                  | Define request, session-view, turn, and stream payloads in shared Zod schemas. Validate trusted senders and payloads. `ask.submit` accepts a session ID, request ID, question, and owned attachment references. Main assembles the transcript and resolves attachments. The renderer never supplies authoritative history or raw capture data for these submissions. |
| Renderer                                                   | Render the main process's session view and preserve the draft across an eligible suspend and resume. Keep draft changes in a session-scoped renderer store or through a small draft IPC, as needed for remounts. Display updates only for the active session and request.                                                                                            |
| `@mauzai/api` and Ask providers                            | Convert ordered role messages and optional labeled images to each provider's input format. Return answer text and preserve the existing progress callback. Keep the API layer free of Electron session state.                                                                                                                                                        |

A session records its ID, verified source identity, whether it is visible or suspended, suspension deadline, resolved provider, completed turns, staged evidence, and any pending request. Generate the session ID in main. Resolve and pin the provider when the first turn starts. If the provider becomes unavailable, show the error and allow retry with that provider or **New chat**. An app-mediated change to provider, model, credentials, or subscription account ends the existing session. Automatic provider selection must never send a prior transcript to a different provider.

Allow one request in flight per session and reject duplicate request IDs. A pending turn has provisional text and its selected attachments. Successful completion commits the user and assistant pair together. A failure keeps the question available for Retry and leaves the completed history intact. Retry uses the original evidence when it is still valid. If it cannot be reused, show the issue and let the user refresh the source or send text only. Blur can leave generation running until completion or expiry. **Stop**, **New chat**, explicit close, expiry, and quit cancel or terminate the request using the provider's available abort mechanism. Invalidate its request identity before asynchronous cleanup so a late result cannot commit. An internal hide during capture does not suspend the chat.

Use a provisional **40 completed pairs** for the visible transcript and **12 completed pairs or 48 KiB of serialized text**, whichever comes first, for a model request. The text budget includes the system instructions and newest question. Trim historic evidence before dropping the oldest complete pairs. Preserve the newest question and available current evidence ahead of older turns. Images have a separate cap and only selected images are sent. There is no automatic summarization in this release. These are product limits for short desktop conversations and should be revisited after measuring real sessions.

### Provider adapters

- **OpenAI API** sends ordered input via the existing Responses API with `store: false`. Include image items for selected attachments only. Retain any required model-specific output metadata when replaying response items. Start with the current HTTP path. Stable prefixes may benefit from provider caching without affecting correctness.
- **Anthropic API** sends alternating structured `user` and `assistant` messages using the existing Messages stream. Attach selected images to the relevant user input and retain the existing stream and error handling.
- **Claude Code and Codex CLI** receive the same bounded dialogue through a clearly delimited transcript in their existing one-shot paths, with the latest user question separately identified. Attach selected images through the existing adapter support. Keep Claude Code's no-session-persistence and Codex's ephemeral mode, as well as existing tool, plugin, and credential isolation. Treat role-like text inside the transcript and captured source material as content.

Provider behavior is documented in the [OpenAI conversation state guide](https://developers.openai.com/api/docs/guides/conversation-state), [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), and [Anthropic Messages guide](https://platform.claude.com/docs/en/build-with-claude/working-with-messages).

## Acceptance and rollout

| Area                        | Acceptance checks                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core interaction            | Verify all three scroll and click cases above. The resumed transcript is visible before send. An unrelated question uses the fresh target. **New chat** starts with zero prior turns.                                                                                                                                         |
| Identity and expiry         | Verify same tab and document, a different tab on the same URL, navigation in one tab, stale extension replies, expiry at the boundary, mixed extension versions, and missing identity.                                                                                                                                        |
| Capture                     | Inspect outgoing requests for text follow-ups, changed selections, screenshots, duplicate crops, comparison with a retained image, and evicted images. Test denied permissions, blocked apps and sites, and a target that changes during capture.                                                                             |
| Request lifecycle           | Verify stream and draft restore across blur, no duplicate turns after failure and retry, Stop, New chat during generation, late results, provider changes, and no capture-triggered activation reset.                                                                                                                         |
| Providers and compatibility | Assert request content and order for all four adapters with fake clients and child processes. Exercise cold Ask and Dictate → Ask. Verify Back, Settings, and Send to agent still follow their normal entry points.                                                                                                           |
| Desktop access and layout   | Exercise mouse and trackpad on macOS and Windows, including Windows with inactive-window scrolling enabled and disabled. Check keyboard and IME handling, focus, readable light and dark themes, long wrapped content, and transcript scroll behavior while streaming. Record any platform behavior that could not be tested. |

Implement in this order after approval:

1. Add the in-memory session lifecycle and tests with an injected clock. Wire explicit close, blur, expiry, and trusted IPC together.
2. Extend browser identity and re-point capture. Cover old extension versions and verify session matching and capture races with injected dependencies.
3. Convert the four provider adapters to use bounded conversation input. Cover roles, selected attachments, pinning, cancellation, and retries.
4. Build the transcript, source controls, and direct resume in the existing Ask panel. Verify Dictate handoff and sibling modes. Record durable UI decisions in the design context as part of the UI change.
5. Run focused tests while developing, then `pnpm check` and the desktop smoke checks. Update the Ask usage notes for the new gestures and session behavior.

Saved cross-device history, a previous-chat list, automatic topic splitting, provider-native sessions, and proactive screenshot monitoring are outside this release.
