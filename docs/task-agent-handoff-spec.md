# Desktop-first task handoff

Applies to **Send to agent**, including tasks staged from Dictate. The selected agent receives the task brief, project folder, and optional screenshot. Codex and Hermes start one task per send. Claude Desktop opens a prefilled Code composer for the user to start the task. A desktop session is usable while the task is queued, running, waiting for review, or complete. The user can work with it without refreshing or restarting the app or waiting for another task.

## Reproduction

Run `TaskAgentLauncher.launch` with an injected macOS environment, a valid project folder, a fake executable, and recording process launchers. Repeat for Codex, Claude Code, and Hermes with and without their desktop bundle in the fixture. The assertion for zero terminal launches fails in all six cases. Each records `open -a Terminal`. The diagnostic used temporary files and injected launchers.

- `TaskAgentLauncher.hasDesktopApp` returned false outside Windows. `openTerminal` started Terminal on macOS, a PowerShell window on Windows, or a terminal emulator on Linux. Windows agent discovery also treated only Codex as potentially usable without a separate CLI. [TaskAgentLauncher](../apps/desktop/src/main/agent/TaskAgentLauncher.ts)
- Codex desktop thread creation omitted approval settings. The Claude desktop route could inherit `default`, `plan`, `dontAsk`, or `bypassPermissions` from saved preferences. The Hermes route supplied no approval policy. [Codex app server](../apps/desktop/src/main/agent/codexAppServer.ts) · [TaskAgentLauncher](../apps/desktop/src/main/agent/TaskAgentLauncher.ts)
- The original launcher suite passed locally with 15 passing and five Windows-only cases skipped. One skipped case asserted that the terminal opened. [Launcher tests](../apps/desktop/tests/TaskAgentLauncher.test.ts)

## Default behavior

| State                                                         | Expected behavior                                                                                                                                                       |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compatible local desktop app installed                        | Open the Claude Code composer or submit to the agent's desktop session or shared desktop backend. Terminal windows stay closed.                                         |
| Desktop app absent and CLI available                          | Run the same agent noninteractively in the background with the requested folder and attachments. Keep the agent's session or local handoff log available for follow-up. |
| Desktop app installed but handoff incompatible or unavailable | Show an actionable error through the existing Send to agent error path. Preserve the draft on a known submission failure.                                               |
| Desktop submission may already have been accepted             | Avoid a second submission. Report the uncertain outcome and direct the user to that agent's session list before trying again.                                           |
| Neither route usable                                          | Surface the missing prerequisite or installation error.                                                                                                                 |

The approved scope is desktop-first on macOS and Windows, with a windowless CLI route on Linux. Look up known app bundle IDs or package identities through the OS with injected results in tests. Recognize the current macOS ChatGPT bundle that hosts Codex, standalone Codex installs that pass the capability check, Claude, and Hermes. Use verified bundled executables or local backends where available, and reuse Mauz's existing CLI discovery for independent installs. Keep the existing agent picker and folder preference contract. Apply the default in the main process without a Settings migration.

Report discovery and startup failures through the current Send to agent error. A successful handoff means the Claude Code composer opened, the agent accepted the task, or the background command started. Later output and execution errors are available in the agent session or the existing local handoff log. Mauz's current retention applies to the local files.

## Routing and permissions

Use the agents' own automatic review features, keep managed restrictions and project trust checks in effect, and apply Mauz's choices to the launch or session. Critical actions that the agent classifies as requiring review can wait for a person in a supported agent UI or be blocked in a headless run. Automatic review has vendor-specific coverage, including for deletions inside the selected workspace. A universal rule that requires human confirmation for every deletion would need a separate enforcement design.

## Confirmed decisions

- Desktop-first on macOS and Windows, with windowless CLI on Linux. CLI fallback only when the same agent's desktop app is absent.
- Codex and Hermes each open a new live session. Claude Desktop opens a prefilled session that starts on confirmation and Send. Each started task can run independently.
- Use vendor-native automatic review. Actions that still need human review can appear in the agent UI or be blocked on a headless route. Global approval settings and access grants are outside the change.

- Screen questions use the captured image and text. Requests for live website research can use the browser shown in the capture when appropriate, with the agent's normal app consent.
